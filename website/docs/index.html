Vimweb documentation

Let visitors follow a link, press a button, or focus a field by typing its on-screen label. Vimweb runs in the browser and has zero runtime dependencies.

Quick start

Install the package in your website project.

npm install @mhariri/vimweb

Import the automatic entry once in your browser bundle.

import "@mhariri/vimweb/auto";

Open the Keyboard shortcuts button at the end of your page. Check Enable keyboard shortcuts, dismiss the guide with Esc, then press f. Type the letters next to a link to follow it.

Try the same sequence here using the Shortcuts button at the top of this page, or open the interactive demo.

Installation

Automatic setup

The @mhariri/vimweb/auto entry waits for the document, creates the guide launcher, and starts shortcuts off for first-time visitors. It remembers each visitor’s choice in local storage when available and keeps open tabs on the same origin in sync.

To place the launcher in a menu or footer, include this button before the automatic entry runs. Vimweb reveals it when ready. Style it with your site's button rules.

<button type="button" data-vim-nav-launcher hidden>
  Keyboard shortcuts
</button>

Plain HTML

After installing the package, copy its JavaScript modules and license into a directory your site serves. Keep the modules together so their relative imports resolve.

mkdir -p assets/vimweb
cp node_modules/@mhariri/vimweb/*.js node_modules/@mhariri/vimweb/LICENSE assets/vimweb/

Load the entry with a module script. This example assumes the page sits alongside the assets directory.

<script type="module" src="./assets/vimweb/auto.js"></script>

You can also download the package archive, unpack it, and copy its JavaScript files and license into the same directory.

Keyboard commands

KeyAction
fLabel visible links and controls. Type a full label to activate its target.
BackspaceRemove the last letter of a partially typed label.
EscCancel hints or dismiss the guide.
j / kScroll down or up by 80 pixels.
g gJump to the top. Press lowercase g twice within 750 milliseconds.
GJump to the bottom.
?Open the guide and change your shortcut preference.

Scroll commands act on the focused scrollable region, or on the page when focus is outside a scrollable region. A hint on a text field or select moves focus there so the visitor can type or choose an option.

Templates and colors

Choose the shape of your guide and hint labels independently from their colors. Set these attributes on <html> for either entry point.

<html lang="en" data-vim-nav-template="terminal"
      data-vim-nav-palette="forest">
AttributeValuesDefault
data-vim-nav-templateclassic has raised keycaps, minimal has flat keys and rounded labels, and terminal has a monospace guide and square labels.classic
data-vim-nav-paletteamber, ocean, forestamber
data-vim-nav-modeauto, light, darkauto

Preview the templates and palettes with real hint labels and controls.

Follow a light or dark site theme

Leave the mode on auto. Vimweb follows the CSS color-scheme on html or body, or a <meta name="color-scheme"> declaration in the head. On a page without a declared scheme, it follows the visitor's system preference.

If your switch sets a class or data attribute, declare the scheme in the same CSS rule. The open guide, hint labels, and native form controls will follow the switch.

:root { color-scheme: light dark; }
:root[data-theme="light"] { color-scheme: light; }
:root[data-theme="dark"]  { color-scheme: dark; }

Customize individual colors

Set custom properties on html or body. The guide uses --vim-nav-surface, --vim-nav-text, --vim-nav-border, and --vim-nav-accent. Hints use --vim-nav-hint-bg and --vim-nav-hint-text. Set text and background colors together to keep labels readable.

:root {
  --vim-nav-hint-bg: light-dark(#18304e, #cfe7ff);
  --vim-nav-hint-text: light-dark(white, #102439);
}

Use --vim-nav-color-scheme: light or dark to choose a scheme just for Vimweb while its mode is auto.

Change appearance from JavaScript

A controller's appearance options override the corresponding HTML attributes. Update just the fields you want to change, including while a visitor is typing a hint. Set a field to undefined to use its HTML value or default again.

import { createVimNav } from "@mhariri/vimweb";

const nav = createVimNav({
  appearance: { template: "minimal", palette: "ocean" }
});

nav.setAppearance({ mode: "dark" });
nav.setAppearance({ mode: undefined });

App integration

Choose the core entry, @mhariri/vimweb, when your app owns the settings UI or page lifecycle. The import is side-effect free. Create one controller per document, in the browser, once the body exists. Use either core setup or automatic setup for that document.

Mount and unmount a controller

This example wires an existing settings button to the guide. The app keeps its own ? binding and gives its editor full control of the keyboard.

import { createVimNav } from "@mhariri/vimweb";

export function mountKeyboardSettings(button) {
  const nav = createVimNav({
    enabled: false,
    disabledKeys: ["?"],
    exclude: ".code-editor"
  });

  button.addEventListener("click", nav.showHelp);

  return () => {
    button.removeEventListener("click", nav.showHelp);
    nav.destroy();
  };
}

Call the returned function when unmounting the page. To save the preference in your own settings store, pass onEnabledChange and use the saved boolean as enabled on the next mount.

Accessibility and focus

The guide uses a native modal dialog and returns focus to the opening control on dismissal. Scroll commands honor the visitor's reduced-motion preference.

Give components their own keys

Text fields, editable content, dialogs, and focused widgets such as comboboxes keep their keyboard interactions. Vimweb also yields during text composition and modifier shortcuts. To claim a key in another component, call event.preventDefault() before the event bubbles to the document.

Reserve commands globally with disabledKeys, or mark a whole region with data-vim-nav-ignore so Vimweb skips its targets and leaves its focused controls alone.

<section data-vim-nav-ignore aria-label="Code editor">
  <textarea aria-label="Source code"></textarea>
</section>

Web components and frames

Hints reach visible controls in the document, open shadow roots, and slots. For a closed shadow root, expose the action on a focusable host. Give controls accessible names and use native links, buttons, and form fields where possible.

A same-origin iframe can have a controller of its own. After the frame loads, pass its contentDocument as the document option. Each frame owns its own installation and cleanup.

API reference

createVimNav(options?)

import { createVimNav } from "@mhariri/vimweb";
import type { VimNav, VimNavOptions, VimNavAppearance, VimNavKey }
  from "@mhariri/vimweb";

The factory accepts VimNavOptions and returns a VimNav controller. All options are optional.

Options

enabled?: boolean
Initial shortcut state. Defaults to true for the core factory. The automatic entry starts off until the visitor opts in.
alphabet?: string
Letters used to build hint labels, in order. Supply at least two distinct lowercase ASCII letters with no duplicates. The default is asdfghjklqwertyuiopzxcvbnm.
disabledKeys?: readonly VimNavKey[]
Commands reserved by your page. Defaults to an empty array. A VimNavKey is one of "f", "j", "k", "gg", "G", or "?".
exclude?: string
A CSS selector for subtrees that own keyboard interaction, such as ".editor, .map". Targets in matching regions are also excluded from hints.
document?: Document
The browser document to install into. Defaults to the current document.
onEnabledChange?: (enabled: boolean) => void
Called with the new state when the guide or app enables or disables shortcuts.
appearance?: VimNavAppearance
Optional template, palette, and mode fields. Each uses the corresponding appearance choices and defaults.

Controller members

readonly enabled: boolean
The current shortcut state.
enable(): void
Enable shortcuts for the document.
disable(): void
Disable shortcuts and dismiss active hints. The settings guide stays available.
showHints(): void
Open hints from a toolbar or command palette. It respects the shortcut state, a reserved f command, current focus, and modal dialogs.
showHelp(): void
Open the shortcut guide and its enable checkbox, including when shortcuts are off.
setAppearance(patch: VimNavAppearance): void
Update selected appearance fields in place. An open guide keeps its focus and an active hint keeps the letters already entered.
destroy(): void
Remove listeners, hints, and the guide, and release the document so another controller can be installed.
